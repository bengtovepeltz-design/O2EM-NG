Rules:

- Do not copy MAME code without preserving copyright/license notices and
  documenting the source file and MAME commit/tag.
- Prefer independent implementation from hardware documentation, using MAME
  only to check behavior.
- No code or table of uncertain provenance enters `src/core_ng/` silently.
- Record every reused table/file here with origin, license and transformation.
- NG-2 did not copy MAME source; the MAME references above informed an
  independent implementation. Runtime differential fixtures are project data,
  not MAME code.

| Source | Origin / version | License | Use |
|---|---|---|---|
| MAME 0.289 `src/devices/video/i8244.cpp` / `i8244.h` | MAME project, `mame0289` tag | BSD-3-Clause | Behavioral reference for the complete register map, write masks/mirrors, A1/A2/A3/A4/A5 semantics, grid/major/quad/minor rendering, collision/priority maps, sound shift register and VBL timer. | `charset_i8244.bin` (512 bytes, CRC32 `b46a3f31`, SHA1 `415382715455b47b69401b3d60bd8f0036dd7fef`) | MAME 0.289 `i8244` ROM region | chip-internal hardware data; MAME BSD-3-Clause | Copied verbatim into `src/core_ng/video/character_rom.cpp` as the i8244/i8245 character generator ROM. | Intel MCS-48 Family User's Manual (machine cycle = 15 oscillator periods) + MAME `odyssey2.cpp` CPU clocks (`17.734476/3` PAL, `7.15909*3/4` NTSC) | Intel / MAME | hardware documentation / BSD-3-Clause | Corrected the NG tick ratio to 180 ticks per 8048 machine cycle. The previous 12-tick value conflated the oscillator with the machine cycle and ran the CPU 15x too fast relative to video. |
| MAME `src/emu/screen.cpp` `time_until_pos` | MAME 0.289 | BSD-3-Clause | Confirmed the absolute VBL line (`vblank_start + vtotal - visible_h`) and that the visible origin is offset from raw vpos. |
| MAME 0.289 `hash/videopac.xml` + `src/devices/bus/odyssey2` | MAME project | BSD-3-Clause | Identified the dedicated `o2_4in1` cartridge slot used by VP40 "4-in-1 Row"; not yet implemented in NG (documented gap, not a VDC issue). |

Semantics confirmed against MAME and encoded in tests:

- The collision and priority maps are cleared at the start of **every
  scanline**, not once per frame. The old frame-global map produced false
  self-collisions.
- Quad characters have a **32-pixel pitch**: 16 drawn pixels plus a 16-pixel
  gap (MAME advances `x += 16` in the outer quad loop in addition to the
  8-column `x += 2` inner loop).
- Color register D4-D7 are not connected on object color bytes, A3 stores all
  eight bits, major Y CAM d0 is not connected, and the horizontal-grid high
  byte only connects d0.
- The VDC writes object registers only while display is disabled; grid
  registers only while the grid is disabled; registers >= 0xF0 are unmapped.

NG-3 did not copy MAME source; the renderer is an independent C++ implementation
of the documented semantics. The only verbatim data is the chip character ROM,
recorded above.

NG-5 does **not** use legacy `vpp_sdl.cpp` as a production architecture. The old
file remains untouched as historical reference only. The new VPP is owned state
inside `core_ng`, uses the single NG tick timeline, and is snapshotted with the
machine.

`b_pin` is hardware metadata: it is derived from the MAME software-list
`feature b_pin=1` by cartridge CRC. It is not a title switch and does not alter
timing. Tutankham, for example, must be `b_pin=0` even though it is a Plus
cartridge; an earlier NG-5 draft incorrectly included every `videopacp`
software CRC and was corrected.

No title-specific timing, palette, IRQ, sprite, VPP or mapper branches exist in
NG-5. Every semantic change was validated across the full local G7000 and
G7400 matrices.
