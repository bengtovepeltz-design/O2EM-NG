## B. Hardware audio architecture

```text
MCS48-NG / MachineBus
        ↓ writes A7/A8/A9/AA at exact NG Tick
AudioDevice (owned hardware state)
        ↓ HBLANK 4/16 prescaler, 24-bit shift register
canonical signed-16 PCM at 48 kHz
        ↓ per-frame host transfer
SDL audio stream (playback only)
```

The i8244/i8245 sound generator is a 24-bit serial shift register clocked from
the HBLANK line, with:

- A7 = high byte, A8 = middle byte, A9 = low byte.
- Output bit = shift-register bit 0.
- Loop feedback of the output into bit 23.
- Optional noise tap on bits 0 and 5 into bit 15.
- 4-line or 16-line HBLANK prescaler.
- Sound IRQ every 24 shifts when VDC control bit 2 is set.
- Output enable at AA bit 7 and 16-step volume at AA bits 0–3.
- AA bit 6 is not connected.

The device is owned by `Machine` and advanced by the same tick as CPU, VDC and
VPP. There is no SDL callback, frame-clock, block counter or title condition
inside it.

---

## C. Audio register map

| Register | Access | Bits | Reset | Effect |
|---|---|---|---|---|
| `0xA7` | write-only | shift1[7:0] (high byte) | 0 | Loads high byte immediately; sets write latch. Reads 0. |
| `0xA8` | write-only | shift2[7:0] (middle) | 0 | Loads middle byte; sets write latch. Reads 0. |
| `0xA9` | write-only | shift3[7:0] (low) | 0 | Loads low byte/output byte; sets write latch. Reads 0. |
| `0xAA` | read/write | b7 output enable, b6 not connected, b5 fast 4-line clock, b4 noise, b3–b0 volume | 0 | Readback returns stored value with b6 forced 0. |
| `0xA0` bit 2 | VDC control | sound IRQ enable | 0 | Enables 24-shift IRQ latch. |

The write latch is consumed at the next HBLANK without shifting; the next
prescaler match shifts the newly loaded pattern. This is MAME's sequencing and
matches the legacy audio8245 observation.

## D. Clock derivation

The NG tick is the authoritative time:

- 1 MCS-48 machine cycle = 180 NG ticks.
- 1 machine cycle = 15 oscillator periods.
- Therefore NG tick rate = `cpu_hz * 12`.

Examples:

| Profile | CPU/oscillator | NG tick rate |
|---|---|---|
| PAL G7000 | 17,734,476 / 3 Hz | 70,937,904 Hz |
| NTSC Odyssey² | 10,738,635 / 2 Hz | 64,431,810 Hz |
| G7400 PAL | 5,911,000 Hz | 70,932,000 Hz |

The shift clock is not a free-running audio oscillator: it is the VDC HBLANK
event divided by 4 or 16. PAL/NTSC therefore differ only through their real
HBLANK/frame geometry, not through a hard-coded pitch.

---

## E. PAL / NTSC timing

- Both profiles use the same hardware algorithm and the same 48 kHz canonical
  PCM rate.
- PAL and NTSC generate 48,000 ±1 samples per emulated second.
- HBLANK spacing follows each profile's `LineTicks()`.
- The fast/slow prescaler is 4/16 HBLANKs in both.
- No normalization or region-specific pitch table exists.

Tests cover PAL and NTSC sample counts and HBLANK-aligned shift timestamps.

---

## F. Shift-register behavior

Implemented exactly as the hardware/MAME model:

1. `signal = shift3 | (shift2 << 8) | (shift1 << 16)`.
2. `output = signal & 1`.
3. `feedback = output`.
4. `signal >>= 1`.
5. If noise: `feedback ^= (signal >> 4) & 1` (pre-shift bit 5).
6. If noise: set bit 15 from feedback.
7. Set bit 23 from feedback (loop sound).
8. Store bytes back.

Tests cover:

- one-bit pattern direction and loop feedback,
- alternating pattern,
- 16-line slow clock and 4-line fast clock,
- write-latch consumption,
- 24-shift IRQ count,
- 24-bit ring behavior.

---

## G. Noise behavior

- Enabled by AA bit 4.
- Tap on pre-shift bits 0 and 5, fed into bit 15.
- 24-bit loop feedback remains on bit 23.
- No `rand()`, host RNG or frame reset.
- Reset state is zero, matching MAME.
- Device tests verify the tap, the disabled path and a deterministic
  200-HBLANK sequence hash/count.

---

## H. Output / amplitude model

The i824x output pin is a 1-bit signal gated by a 16-step volume duty at the
device clock. The console's analog path low-pass filters that multi-MHz carrier.
NG models the audible result directly:

```text
logical amplitude = (output_bit && AA.bit7) ? 16384 * (AA & 0xF) / 16 : 0
```

This is signed 16-bit full scale, with maximum 15,360 at volume 15 (0.46875
full scale), matching MAME's 0.5 logical output times the 15/16 duty average.

- Hardware logical amplitude lives in the device.
- MAME's 0.25 route gain is a mixer/presentation choice; NG applies it only in
  the SDL host adapter.
- User volume/EQ/reverb is not part of machine state.

Tests: volume 15 = 15,360; volume 8 = 8,192; volume 0 and enable-off = silence.

---

## I. Timestamped write model

Every sound write is applied at the exact NG machine tick:

```text
AudioDevice::AdvanceTo(write_tick)  // old state generates only before
apply register write
continue from new state
```

The VDC supplies the bus-access tick; the AudioDevice never receives a
frame-relative or block-relative timestamp.

Tests verify:

- `LastWriteTick()` equals the MOVX instruction-start tick (1,800) in a
  synthetic CPU program,
- the MOVX completes two cycles later (2,160),
- a volume/disable write at a sample boundary affects only later samples.

---

## J. Scheduler integration

- `Machine::PowerOn()` configures the device and attaches it to the VDC.
- `Vdc::AdvanceTo()` clocks `AudioDevice::Hblank()` at `next_hblank_tick_` and
  finishes with `AudioDevice::AdvanceTo(tick)`.
- `Machine::RunFrame()` advances video/audio, drains the canonical PCM and
  calls the host `PushAudio` once per frame.
- No async thread touches hardware state. Only host consumption is outside the
  machine thread.

---

## K. Canonical PCM format

- Signed 16-bit little-endian mono.
- Default 48,000 Hz (configurable at configure time; tests also use 44.1 kHz).
- Logical full scale ±32,767.
- Deterministic FNV-1a hash over the sample bytes.
- Headerless raw output or RIFF/WAVE export.

`audio_render_probe` writes WAV plus sample count, start/end tick, profile and
hash.

---

## L. Resampler

The tick→PCM stage is a deterministic, phase-continuous **area resampler**:

- Phase is exact rational `ticks * rate * tick_hz_den / tick_hz_num`.
- Every sample boundary splits at hardware event boundaries.
- The sample value is the exact average amplitude over its tick interval.
- No floating point, no frame reset, no cumulative drift.
- Changing host rate changes the configured sample interval, not hardware
  timing.
- 48 kHz and 44.1 kHz are tested; PAL/NTSC both produce 48,000 ±1
  samples/second.

This is deliberately simple: the hardware signal is a low-frequency envelope;
a band-limited audiophile filter is not needed before hardware accuracy is
proven.

## M. Host SDL adapter

`src/ng_host/sdl_ng_host.cpp`:

- Opens `SDL_AUDIO_DEVICE_DEFAULT_PLAYBACK` as 48 kHz mono S16.
- `PushAudio` queues already-generated canonical PCM with
  `SDL_PutAudioStreamData`.
- Applies a 0.25 presentation gain to match MAME's route.
- If the host queue exceeds 96,000 bytes (1 s mono S16) during
  fast-forward/pause, it drops stale host samples; it never slows or changes
  the emulated clock.
- Destroys the stream with the host.

The device never contains an SDL handle. The host adapter performs no
oscillator, pitch, start/stop or shift timing.

---

## N. Reset / power-on

`AudioDevice::Reset(now)` clears:

- AA, A7/A8/A9, prescaler, shift count, pending/write latches, output and IRQ.
- PCM phase/accumulator and pending PCM buffer.
- `last_tick = now` (power-on uses 0; mid-run reset uses the current tick).

Tests cover PowerOn and mid-run Reset. No frame-boundary phase reset exists.

## O. Save-state

- sound register,
