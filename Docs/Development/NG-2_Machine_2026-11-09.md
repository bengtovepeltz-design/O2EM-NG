## C. Machine architecture

```text
frontend / SDL / database
        |
        v
   o2em::ng::Machine
        |
        +-- Scheduler (one ordered event queue)
        +-- HardwareProfile + global Tick timebase
        +-- MCS48-NG CPU (owned state)
        +-- MachineBus (Philips decode)
        |     +-- BIOS 1KB
        |     +-- Cartridge + Mapper
        |     +-- 128-byte external RAM
        |     +-- StubVdc (NG-2 only)
        |     +-- input + BUS latch + P1/P2 + T0/T1
        +-- BusTrace (disabled by default)
        +-- Snapshot writer/reader
```

`Machine` owns all mutable state. Devices do not use globals, SDL, the
frontend or the database. The CPU talks only to `Mcs48Bus`; `MachineBus`
implements that interface and owns the Philips-specific decode.

Lifecycle:

```text
Create -> Configure -> LoadBIOS/LoadCartridge -> PowerOn
       -> RunFrame/RunCycles/RunInstructions/RunUntil
       -> SetInput/ScheduleInput -> SaveState/LoadState -> GetInfo
```

Power-on and reset are deliberately different:

- `PowerOn`: clears CPU state and internal RAM (CPU `PowerOn`), clears the
  6810 external RAM, resets mapper/VDC/ports, sets machine time to 0, clears
  the scheduler and schedules the first VBL event.
- `Reset`: resets CPU/mapper/VDC/ports, keeps CPU internal RAM (hardware RESET
  does not clear it), keeps external RAM, keeps machine time and scheduler
  phase, and closes any open VDC IRQ latch. P1/P2 return to 0xFF input mode.
- `LoadCartridgeBytes` after power-on intentionally calls `Reset`; normal
  deterministic test/frontend flow loads images before `PowerOn`.

## D. Authoritative timebase

One monotonic machine clock exists:

```text
12 ticks == 1 MCS-48 machine cycle
Tick = int64, absolute, never reset per frame
```

The factor 12 makes both console families exact with integer tick periods:

| Profile | CPU clock | Pixel clock | Ticks/pixel | Line | Frame |
|---|---|---:|---:|---:|---:|
| PAL G7000 | 17,734,476 / 3 = 5,911,492 Hz | 2*17,734,476/5 = 7,093,790.4 Hz | 10 | 4,560 | 1,427,280 |
| PAL C52  | 17,812,000 / 3 | 2*17,812,000/5 = 7,124,800 Hz | 10 | 4,560 | 1,427,280 |
| NTSC O2  | 7,159,090 * 3/4 = 5,369,317.5 Hz | 7,159,090 Hz | 9 | 4,095 | 1,076,985 |

PAL NTSC are two `HardwareProfile` instances of one architecture. No legacy
`master_clk`, `h_clk`, `LINECNT`, `VBLCLK`, `/20`, `/22` or frame-local reset
exists. No floating point is used in timing. `MulDivFloor` provides exact
rational phase calculations.

PAL frame rate is 49.69 Hz; NTSC is 59.83 Hz.

### VBL IRQ phase (MAME-verified)

MAME's i8244 schedules the VBL timer with
`screen().time_until_pos(m_vblank_start, m_hblank_start - 1)`.
`screen_device::time_until_pos()` measures scanlines relative to VBLANK and
adds `m_height - (m_visarea.bottom() + 1)`. The absolute line is therefore:

```text
vblank_start + (vtotal - visible_h)
PAL:  242 + (313 - 243) = 312
NTSC: 242 + (263 - 243) = 262
```

NG-2 uses that absolute line and `hblank_start - 1`. This was verified with a
MAME 0.289 breakpoint on the 8048 IRQ vector 0x003: first assertion at
0.020111646 s on PAL, then once per 20.12 ms frame. Initial NG-2 code used
line 242 directly and was corrected; this was the first real machine-level
divergence found by the differential.

## E. Scheduler

`Scheduler` keeps a small sorted vector of pending events, never a heap of
`std::function`. Total order is:

```text
(tick, priority, sequence)
```

Priorities: CPU, IRQ, Video, Timer, Input, Audio, Presentation. Sequence is a
monotonic tie-breaker. `AdvanceTo(tick)` executes all due events in order and
moves `Now`; `RunDue` executes only due events. Handlers are stable integer
`HandlerId`s, so the whole pending queue snapshots and restores.

The machine uses events for VBL IRQ, scheduled input, scheduled pin
transitions and future device/frame/audio/VPP work. The scheduler avoids
cloning MAME's scheduler; it implements only what this machine needs, with
explicit reproducible ordering.

Tests: same-tick priority/sequence ordering, out-of-order insertion, `Now`
semantics, pending-queue snapshot/restore and replay.

## G. Program memory map

```text
0x000-0x3FF  MCS-48 internal BIOS ROM (never cartridge)
0x400-0xBFF  cartridge 2KB window A
0xC00-0xFFF  cartridge 1KB window B
```

BIOS is a 1KB image (G7000/G7400/Jopac/C52). Cartridge reads always go through
the mapper; BIOS is always visible at 0x000-0x3FF regardless of P1.

Standard mapper window behavior (MAME `o2_rom`):

```text
read_rom04(offset) = rom[(offset + bank*0x800) & mask]
read_rom0c(offset) = read_rom04(offset + 0x400)
bank = P1[1:0]
mask = bit_floor(rom_size) - 1
```

Consequences verified against MAME and the local library:

- 2KB image: both windows mirror the same 2KB.
- 4KB image: two 2KB banks; P1[0] selects; P1[1] aliases.
- 8KB image: four 2KB banks; P1[1:0] selects.
- 3KB-page image: 0x400-0xBFF is page+0x000..0x7FF; 0xC00-0xFFF is
  page+0x800..0xBFF; P1[1:0] selects one of 1/2/4 pages.
- 16KB raw image: MAME's default is the Rally/VP55-60 latch mapper.

CRC is identity only. No CRC selects timing, video or a title workaround.

## H. External memory / I/O map

MAME `odyssey2_state::io_read/io_write` semantics are implemented:

```text
MOVX read:
  data = cart.io_read(addr)                  (0xFF for standard carts)
  if P14=0 and A7=0: data &= extRAM[addr&0x7F]
  if P13=0 and P16=0: data &= i824x.read(addr)

MOVX write:
  if P16=0:
      cart.io_write(addr, data)
      if P14=0 and A7=0: extRAM[addr&0x7F] = data
  if P13=0:
      i824x.write(addr, data)
```

External RAM is 128 bytes. Addresses 0x80-0xFF are not RAM even when P14=0;
they fall through to cartridge/VDC/open bus. Tests cover 0x00, 0x7F, 0x80,
0xFF and P1 variants.

## I. P1/P2 decode table

P1 (quasi-bidirectional, active-low chip selects):

| Bit | Signal | Hardware meaning | Effect |
|---:|---|---|---|
| 0 | P10 | cartridge bank A | mapper bank bit 0 |
| 1 | P11 | cartridge bank B | mapper bank bit 1 |
| 2 | P12 | keyboard/joystick matrix enable | low enables P2 keyboard and BUS joystick |
| 3 | P13 | i824x chip select | low selects VDC for MOVX read/write |
| 4 | P14 | external RAM chip select | low selects RAM when A7=0 |
| 5 | P15 | Videopac+ VPP chip select | reserved for NG-3 VPP |
| 6 | P16 | external bus write enable | low enables cartridge/RAM writes; VDC read also requires low |
| 7 | P17 | luminance | video only, not decoded by NG-2 bus |

P2:

| Bits | Meaning |
|---|---|
| P20-P22 | 74156 keyboard row select / joystick select |
| P23 | additional decoder input |
| P24 | 74148 GS (priority encoder) |
| P25-P27 | 74148 encoded key position (active-low data) |

Keyboard read (`IN A,P2`, P12 low): row = P2[2:0]; the 74148 encodes the
highest-priority pressed bit. The machine returns `(inp << 5) | 0x0F` before
the CPU's latch AND, matching MAME.

BUS read (`INS A,BUS`, P12 low): selector P2[2:0] 0/1 selects left/right
controller; pressed bits are active low (up=bit0, right=bit1, down=bit2,
left=bit3, fire=bit4). Selectors 2-7 leave BUS at the cartridge value.

Tests cover all P1 chip-select combinations, P2 keyboard rows, both joysticks,
and invalid selectors.

## J. Cartridge types

Implemented and tested for the local library:

| Size | Kind | Mapper |
|---:|---|---|
| 0x0800 | 2KB standard | Standard (bank ignored) |
| 0x0C00 | 3KB single page | ThreeK (1 page) |
| 0x1000 | 4KB standard | Standard (2 banks) |
| 0x1800 | 6KB (2 x 3KB) | ThreeK (2 pages) |
| 0x2000 | 8KB standard | Standard (4 banks) |
| 0x8000 | 32KB standard raw | Standard (P1 selects first 8KB) |
| 0x3000 | 12KB (4 x 3KB) | ThreeK (4 pages) |
| 0x4000 | 16KB Rally/VP55-60 | Rally latch |
| other power-of-two >32KB | explicit unsupported | none |

MegaCART/XROM are not present in the local library. They are not guessed:
an unsupported image clears the cartridge and returns false from
`Machine::LoadCartridgeBytes`, so arbitrary bytes are never executed. A future
mapper can implement the same `Mapper` contract without changing the machine.

## K. Mapper implementation

- `StandardMapper`: 2KB window, P1[1:0] bank, bit-floor mask, MAME `o2_rom`
  behavior. Used for 2KB/4KB/8KB images.
- `ThreeKMapper`: 3KB pages, P1[1:0] page select, page mask for 1/2/4 pages.
  Used for 3KB/6KB/12KB images (including 12KB KTAA).
- `RallyMapper`: control = P1 & 0x13. P10=1 forces the last 8KB bank; P10=0
  selects the latch. A MOVX write with A7=1 updates the latch only when P14=0.
  Read index `(offset + bank*0x800) & (rom_size-1)`.
- All mappers snapshot bank/control and restore with a typed magic.
- Reset bank and P1=0xFF behavior match MAME's i8048 reset + driver
  `p1_write`.

Tests: reset bank, bank switch, window visibility, BIOS overlay immunity,
P1 aliasing, 3KB page boundaries, Rally latch/A7/P14/P10 behavior, snapshot.

Rally/VP59 lessons from earlier historical work are encoded as generic latch
and bank tests, not title hacks.

## L. Open bus behavior

MAME's `o2_cart_slot_device::io_read()` returns 0xFF when no cartridge claims
the access; standard cartridges also return 0xFF. NG-2 documents and tests the
deterministic value **0xFF** for unclaimed MOVX reads. VDC/RAM/cartridge
outputs are wired-AND (each selected device ANDs its value), matching MAME.

No assumption of 0x00 is made. If future hardware evidence shows a different
idle value, `MachineBus::kOpenBus` is the single place to change; it is
recorded as an implementation choice, not as proven hardware data.

## M. IRQ plumbing

```text
VBL scheduler event -> StubVdc::AssertVblankIrq
                    -> VDC IRQ line
                    -> MachineBus::IrqLine
                    -> CPU SetIrqLevel before each Step
                    -> CPU CheckIrqs before fetch
                    -> vector 0x003, 2-cycle entry
A1 read -> StubVdc clears IRQ/control_status
        -> MachineBus line low
        -> CPU SetIrqLevel(false)
RETR -> clears in-service
next VBL -> reasserts
```

`DIS I` disables service but does not discard a held level. `EN I` services
the held level at the first eligible fetch. Tests cover service, A1 clear,
RETR, second VBL reassertion, DIS I/EN I hold, and timer IRQ interaction.

---

## N. T0/T1 plumbing

- T1 normally comes from `StubVdc::Vblank() || Hblank()` at the current tick.
- T0 normally comes from the mapper/cartridge (0 for standard carts).
- Machine tests can override T0/T1 deterministically and schedule pin
  transitions on exact ticks.

Tests cover T0 high/low branches, T1 high/low branches, two falling edges with
timer wrap, overflow flag, and scheduled waveform transitions. The CPU owns
counter semantics; the machine supplies the pin level at machine time.

Known NG-2 limitation: the CPU samples T1 once per instruction (`SetT1` before
`Step`) rather than per burned cycle. Tests schedule edges with instruction
separation. Per-cycle pin sampling should be revisited if a real cartridge
differential exposes a mid-instruction T1 edge that changes timer state.

## O. Input model

`MachineInput` contains two controllers and an 8x8 active-high keyboard
matrix. There are no SDL keycodes in the core. Input can be set immediately or
scheduled:

```text
ScheduleInput({tick, Controller1/2, index, value})
ScheduleInput({tick, KeyboardRow, row, bits})
ScheduleInput({tick, ResetButton, 0, level})
```

The scheduler applies transitions at exact machine ticks. Tests drive joystick
fire down/up, keyboard key down/up, and verify active-low BUS/P2 values at
chosen ticks. Input state is part of the snapshot.

## P. Stub VDC role

`StubVdc` is deliberately not a renderer. It implements only bus-visible
behavior needed to execute BIOS/cartridge code:

- A0 control, position-strobe/live-beam bit, display/grid write guards.
- A1 status: VBL latch bit3, hstatus bit0, position-strobe bit1; reading
  clears IRQ and control bits 0xCC.
- A2 collision status read/clear (always 0 in NG-2).
- A4/A5 Y/X beam, live or latched from the same global tick.
- Register mirroring (quads, A0-AF at B0-BF), write-only/unused registers,
  color/grid data masks.
- VBL/HBlank/T1 signal and IRQ line.

There is no framebuffer, palette, sprite renderer, sound shift register or
raster hack. NG-3 replaces this with the real i8244/i8245.

### S3. Real BIOS + vp_01 prefix

The first 4,261 PC values from reset (cartridge entry onward) match MAME
exactly (`0x44b7f94c07942a55`). MAME's first IRQ vector at index 4,261 is the
VBL phase boundary described in section D.

### First divergence found and fixed

1. **Initial VBL phase**: NG-2 initially scheduled the VBL IRQ at absolute
   line 242. MAME's `time_until_pos` measures from VBLANK, so the absolute
   line is 312 PAL / 262 NTSC. Fixed in `HardwareProfile::VblankIrqOffset()`.
2. **CPU reset P1/P2**: NG-1 reset both ports to 0; MAME 0.289 and the MCS-48
   reset description put them in input mode (0xFF). NG-2 real-BIOS execution
   exposed this immediately. Fixed in `Mcs48Cpu::Reset()` with the NG-1 reset
   test updated. NG-1 remains green at 667 checks.
3. **No CPU opcode/cycle semantic divergence** was found in the runtime
   fixtures. Source-level NG-1 already had 0/256 cycle and legality mismatches.

## T. First divergence - detail

The synthetic fixture matched for all 15,779 instructions, so no CPU semantic
difference exists in that tested path. The real-BIOS frame-boundary comparison
showed a state difference at frame 1. Investigation with MAME debugger
breakpoints and traces established:

- instruction sequences match up to the first IRQ;
- MAME's first IRQ vector is at 0.020111646 s PAL;
- the VBL timer absolute line is `vblank_start + (vtotal - visible_h)`;
- the remaining few-cycle difference at a frame boundary is VDC/scheduler
  phase, not CPU, bus or mapper semantics.

No title-specific workaround was added.

## U. Bus trace and replay

`BusTrace` records compact POD records:

```text
tick, cpu_cycle, pc, operation, address, data, P1, P2, mapper bank, device
```

Operations: program fetch, MOVX read/write, port read/write, BUS read/write,
IRQ transition, T0/T1 transition, mapper write.

Filters: tick range, PC range, operation mask, include/exclude program fetch,
maximum record count. Disabled by default; truncation is explicit. Tests check
field derivation (cpu_cycle = tick/12), max records, PC/time/op filters, and
fetch exclusion.

Replay tests feed a known transaction sequence to `MachineBus` twice and
compare returned values plus final external RAM, VDC registers, P1/P2 and
mapper state.

## V. Save-state determinism

The snapshot contains:

- profile signature (geometry, pixel ticks, CPU rational clock, region);
- global machine tick and frame count;
- CPU complete state (including RAM, timer/prescaler, ports, IRQ state);
- scheduler `now`, sequence and every pending event in order;
- bus: external RAM, P1/P2, BUS latch, expander, T0/T1 overrides;
- mapper bank/control;
- stub VDC registers, status, latches and IRQ line;
- machine input and last observed IRQ/T0/T1 levels;
- BIOS/cartridge CRC and size identity.

BIOS/cartridge bytes are configuration, not mutable state; restore rejects a
snapshot whose BIOS/cart identity or profile does not match.

Test procedure:

```text
run 5,000 instructions
schedule a future input event (pending scheduler state)
save
run 3,000 instructions, capture CPU state + bus trace
restore
run the same 3,000 instructions
compare Now, full state hash, trace size and every trace field
```

Result: exact match, including pending-event replay order.

## Z. Recommendation for NG-3

Proceed to the real i8244/i8245 renderer with the NG-2 machine unchanged:

1. Replace `StubVdc` behind the existing bus interface with a real i8244/i8245
   device using the same global tick/profile.
2. Implement sprite/quad/grid rendering, collisions, sound shift register,
   priority and the real A1/A2/A4/A5 semantics.
3. Add VPP/EF934x for G7400/Jopac/Odyssey3 on the same bus decode; do not add
   title or CRC timing branches.
4. Add frame presentation/audio host callbacks through `MachineHost`.
5. Extend runtime differential with rendered frame/collision fixtures; keep
   the synthetic bus/CPU fixture as a regression gate.
6. Revisit per-cycle T1 sampling only if a real cartridge differential proves
   a mid-instruction edge matters.

Do not use this mission to add legacy `cpu.cpp`/`vmachine.cpp` fixes. The new
machine is the future.
