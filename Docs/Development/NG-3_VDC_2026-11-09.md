## B. VDC architecture

`Vdc` is a single owned-state device. It owns the 256-byte register file, the
latched A1 status, the A2 collision status/mask, A4/A5 latches, the live beam
state, per-scanline collision and priority maps, the 360x243 indexed
framebuffer pair (live + presented), the sound shift register and the raster
cursor. There is no global VDC state and no side channel.

One timebase: every beam, blanking, IRQ and raster value is a pure function of
the authoritative NG `Tick`. `AdvanceTo(tick)` advances the raster; `Read`/
`Write` first advance the raster to the write's beam position (update-on-write)
and then apply the access. PAL and NTSC are two profile instances of the same
class (`i8245`/`i8244`), not separate renderers.

## C. PAL / NTSC geometry

| | PAL i8245 | NTSC i8244 |
|---|---|---|
| pixels/line | 456 | 455 |
| lines/frame | 313 | 263 |
| ticks/pixel | 10 | 9 |
| line ticks | 4560 | 4095 |
| frame ticks | 1,427,280 | 1,076,985 |
| HBlank | 366..453 | 366..452 |
| VBlank state | 242..312 | 242..0 |
| BG sync | 414 | 413 |
| visible | 360x243 | 360x243 |

8048 machine cycle = 180 ticks for both (PAL: 18 pixels × 10; NTSC: 20 pixels
× 9). This is the correction that makes the CPU run at the real ~394 kHz
machine-cycle rate instead of 15× too fast.

## D. Register map

Implemented (hardware offsets, MAME 0.289 semantics):

- `0x00..0x0F` 4 minor sprites (y, x, color, unused).
- `0x10..0x3F` 12 foreground major objects (y, x, ptr, color).
- `0x40..0x7F` 4 quads × 4 characters (y, x, ptr, color); quad y/x mirror to
  the first character.
- `0x80..0x9F` 4 sprites × 8 shape bytes.
- `0xA0` control, `0xA1` status (read clears), `0xA2` collision (read clears),
  `0xA3` color, `0xA4` Y beam, `0xA5` X beam.
- `0xA7..0xA9` sound shift, `0xAA` sound control.
- `0xC0..0xC8` horizontal grid low, `0xD0..0xD8` horizontal grid high,
  `0xE0..0xE9` vertical grid.
- `0xA0..0xAF` mirrored at `0xB0..0xBF`; `>= 0xF0` unmapped.
- Object registers are write-guarded while display is enabled; grid registers
  are write-guarded while grid is enabled.
- Masks: object color D4-D7 not connected (`(offset & 0x83)==0x03`), A3 stores
  all 8 bits, major Y CAM d0 not connected, horizontal-grid high byte only d0.

## E. A0 control semantics

`0x02` position strobe (falling edge latches A4/A5), `0x04` sound IRQ enable,
`0x08` grid enable, `0x10` external-collision IRQ enable, `0x20` display
enable, `0x40` grid dots, `0x80` wide grid. Mid-frame A0 writes take effect
from the beam position of the write onward through the raster advance.

## F. A1 / status / IRQ

Latched high bits: `0x04` sound, `0x08` VBlank, `0x40` external collision,
`0x80` major-priority collision. Live bits: `0x01` hstatus window, position
strobe. Reading A1 clears the latched high bits and deasserts the IRQ. The
VBlank event is a scheduler event at `HardwareProfile::VblankIrqOffset()`; the
machine advances the VDC to the event tick before latching, so pre-VBL pixels
use pre-IRQ state. IRQ works with the MCS48-NG level-sensitive input.

## G. A2 collision semantics

Read-clear status; the A2 register is the source mask. Sources: minor 0..3
(`0x01..0x08`), grid vertical/horizontal (`0x10/0x20`), external CX (`0x40`),
major (`0x80`). Both "I collide with an already-drawn source" and "an
already-drawn object would collide with me" directions are applied, as in
MAME. Collision and priority maps are **cleared at the start of every
scanline**; this fix removed false cross-scanline self-collisions.

## H. A3 color semantics

Background = `bitswap3(color, 3,4,5)`; grid = `bitswap4(color, 6,0,1,2)`;
major color = `8 + ((color>>1)&7)`; minor color = `8 + ((color>>3)&7)`. Logical
indices 0..15; the canonical MAME pre-RF i8244 palette is used for dumps.
Presentation palette/RF work is deferred.

## I. A4 / A5 beam semantics

A4 = `get_y_beam()`: resets before HBlank on line 0, increments at BG sync,
clamps at 263. A5 = `hpos >> 1`. With the strobe bit set the value is live;
with it clear the latched X/Y is returned. This is the exact boundary set
tested for PAL and NTSC.

## J. Raster / update-on-write model

The raster cursor advances monotonically with `AdvanceTo`. Before a write the
raster is advanced to the current beam and the write is then applied; partial
scanlines and mid-frame control/color/object/grid changes therefore affect only
subsequent pixels/lines. Frame wrap renders through the last visible line,
finalizes the presented frame, clears maps and starts the next frame. No
whole-frame redraw with later compensation, no frame-local clock.

## K. Framebuffer model

`Framebuffer` (in `video/framebuffer.h`) stores indexed8 pixels, width/height/
stride, and a frame number. `Framebuffer()` returns the last completed frame
(presented); `LiveFramebuffer()` returns the partially rendered current frame
for tests. FNV-1a hashes are used for determinism.

## L. Grid

Horizontal segments (9 positions × 3 lines), grid dots (control `0x40`), and
vertical segments (8 bands × 10 columns) with normal/wide width are
implemented. Grid collision bits `0x20`/`0x10` are recorded. Mid-frame grid
enable/disable and writes are honored by the raster advance.

## M. Minor sprites

4 sprites, 8×8 shape bytes, X/Y/clip, 2× or 4× zoom, X9/S attribute shifts,
left/right/top/bottom clipping, per-pixel collision and the zoom collision
high bit. Mid-frame register changes are honored.

## N. Major objects

12 foreground objects with y/x/ptr/color, Y CAM d0 masking, character height
`7 - ((y>>1)+ptr)&7` (0→8), 8×2 character rows, clipping and priority.
NTSC skips objects with `y < 0x0E`; PAL draws them.

## O. Quads

4 quads × 4 characters. The quad origin is the first character; the height is
determined by the fourth character's pointer. **Character pitch is 32 pixels**
(16 drawn + 16 gap), matching MAME's outer `x += 16` in addition to the inner
8-column `x += 2`. This was a significant NG-3 defect: the initial 16-pixel
pitch caused wrong dot spacing and broke overlapping-quad timer displays.

## P. Clipping

All layers clip at the 360×243 visible rectangle and at the segment boundaries
used during partial raster updates. Border-crossing sprites, quads and majors
are tested.

## Q. Priority

Composite order is grid, then major (quads first, then foreground), then minor.
The priority map implements MAME's "earlier higher-index object wins" rule and
sets the A1 major-priority bit `0x80` on overlap. Maps are per scanline.

## R. Collision engine

Per-pixel source bits plus the edge pass (grid/minor left of a major; grid to
the left of a non-zoomed minor) implement MAME's hardware collision semantics.
External CX collision is provided for future VPP composition. Tests cover
minor/minor, major/minor, major priority, grid, external and isolation.

## S. Save state

The VDC snapshot (`"VDC3"`) contains the profile, tick/frame state, raster
cursor, full register file, control/collision status, A4/A5 latches, IRQ latch,
collision/priority maps, sound state, presented framebuffer and live
framebuffer. The machine snapshot version is 2. Mid-frame save/restore of the
presented frame, status and a pending VBL IRQ is bit-identical.

## T. MAME differential methodology

- Reference: local MAME 0.289 (`mame0289`), `videopac` driver, same BIOS
  (`o2bios.rom` CRC `8016a315` = local `G7000.bin`) and same cartridges.
- Renderer: the real game writes the VDC register file; the probe runs the NG
  machine and dumps the presented frame, while MAME captures the screen with
  the same scripted input and frame count. Structural comparison is lit-mask
  cell IoU plus row/column correlation on a 45×30 grid.
- Execution: the MAME debugger `trace` (noloop) PC stream is compared with the
  NG per-instruction PC stream. The full ~50-frame no-input trace matched
  instruction-for-instruction (199,462/199,551, with only the known IRQ-phase
  resync), proving the machine and the corrected timebase are in lockstep.
- Finding: the historical capture script uses `emu.keypost("ENTER")`, which
  MAME interprets as the letters E-N-T-E-R, not the Enter key. Fresh captures
  using a real newline/Enter were generated for diagnosis. This explains why
  some stored reference screens show a "PRESS ENTER"/pre-start state.

## Y. Legacy regression comparison

The legacy `vdc_stub`/`vmachine` path was not modified. Legacy captures were
used only as historical evidence. The real VDC explains several legacy
kludges: the 15× CPU:video ratio error, frame-global collision maps, and the
16-pixel quad pitch. No legacy correctness code was ported.

## Z. Exact recommendation for the next phase

1. **NG-2 cartridge slots:** implement the `o2_4in1` mapper (VP40) and verify
   the 3K/Rally variants against MAME. This is the only blank mandatory probe.
2. **CPU/video phase:** align the last one-instruction IRQ phase difference
   (likely a single instruction's cycle count) so raster-synchronized display
   updates (VP01 prompt head, VP15 status) land on the same scanline as MAME.
   Do not tune title offsets; fix the shared cycle model.
3. **NTSC title captures:** generate a stored MAME NTSC reference set and add
   title-level NTSC structural probes.
4. **NG-5 VPP:** use the inert external-collision/IRQ hooks already present for
   EF9340/EF9341 composition; do not add a second video clock.

## Remaining hardware ambiguity

- MAME's VBlank timer uses `screen().time_until_pos(vblank_start,
  hblank_start-1)` with a visible-origin offset; the derived absolute line was
  confirmed against `screen.cpp`. A one-instruction difference remains between
  NG and MAME at the first IRQ, which is a CPU cycle-boundary detail, not a VDC
  register/beam semantic.
- The game-visible difference for VP01/VP15 arises from a raster-synchronized
  display update where the game enables display mid-clear; the number of
  objects accepted depends on cycle-exact timing. NG implements the correct
  display-enable write guard and update-on-write; the residual is the IRQ
  phase above.
- MAME's stored reference captures used `emu.keypost("ENTER")` (letters), so
  some references document a pre-start state.

## Provenance

See `Docs/Development/NG-0_Provenance.md`, NG-3 section. The renderer is an
independent C++ implementation of MAME's documented BSD-3-Clause behavior. The
only verbatim data is the chip-internal 512-byte i8244 character ROM
(CRC32 `b46a3f31`), recorded with license and transformation.
